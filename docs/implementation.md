# Реализованный MVP и границы

Архитектурный документ описывает целевую систему. В этом репозитории реализован следующий проверяемый срез.

| Область | Сейчас |
| --- | --- |
| Компания | Одна организация на установку; org scope сохраняется в данных и RLS |
| Вход | Демо только на loopback; enterprise OIDC с PKCE, state, nonce и проверкой корпоративного домена/tenant |
| Публикация | CLI, MCP stdio, JSON-пакет через интерфейс; атомарное переключение релиза |
| Данные | PGlite локально, PostgreSQL для enterprise; API брокера, JSON Schema, RLS под ограниченной ролью |
| Шаринг | Пользователи/группы, просмотр/изменение данных, независимая роль builder |
| Изоляция UI | Iframe без same-origin, CSP и привязанный к запуску MessageChannel |
| Функции | Отдельный runner с gVisor; отключены без явной конфигурации |
| Секреты | AES-256-GCM, write-only API; нет выдачи секретов приложению и реализации коннекторов |
| Копия | Новый app ID, код и схема; без записей, комментариев и чужих grants |
| Жизненный цикл | Предупреждение после 60 дней простоя, архив через 7 дней; pinned исключены |
| Каталог | Полный снимок Google/Microsoft; отзыв сессий, замена владельца, fail-closed после 5 минут без синхронизации |
| Размещение | Docker Compose API + PostgreSQL; runner устанавливается отдельно на Linux |

## Где проходит граница безопасности

Код приложения не запускается в процессе API. Data Broker сейчас является модулем этого доверенного процесса, а не отдельным сервисом. Подключение API имеет права миграций; операции с записями переключают роль транзакционно в `coship_data_runtime`, без BYPASSRLS. Это защищает от выхода через прикладной контракт, но не от компрометации самой платформы или администратора БД. Разделение мигратора, control plane и брокера на разные сервисные роли — дальнейшее усиление.

Права проверяются на каждом запросе, но уже показанные пользователю данные нельзя отозвать из его памяти или скриншотов. Роль builder позволяет менять код, который исполняется у пользователей с доступом: выдавайте её доверенным авторам. Сканер секретов эвристический, а CSP не является доказательством отсутствия всех каналов утечки при исполнении злонамеренного UI. Проверки не следует выдавать за независимый аудит безопасности.

Отключение пользователя через каталог обрабатывается после следующего успешного полного снимка. Неполный или ошибочный снимок не обновляет freshness. Администратору оставлены операции восстановления управления при устаревшем каталоге, но доступ к данным блокируется. Вложенные группы пока не раскрываются: адаптер передаёт прямое членство.

## Проверки

Тесты покрывают публикацию и откат, доступ и отзыв прав, межорганизационные границы и RLS, схемы/ревизии/идемпотентность, копирование без данных, офбординг, архивацию, шифрование, ограниченные CLI-токены, реальные процессы CLI/MCP и OIDC с локальным тестовым IdP. Браузерные тесты в Chrome проверяют создание, записи через SDK, комментарии, шаринг с запретом записи для viewer, копирование, архив и мобильную ширину.

На 10 октября 2026 года прошли 19 тестов на PGlite, 13 тестов платформы на отдельном PostgreSQL и 2 браузерных сценария Chrome; TypeScript и production-сборка также проходят.

Корпоративные Google/Microsoft tenants, сетевые сбои их API и Linux/gVisor требуют отдельной интеграционной приёмки. На macOS runner намеренно не запускается. Нельзя считать эти пути проверенными только по TypeScript или тестовому IdP.

## Что пока отсутствует

Внешние коннекторы и их ACL, биллинг по местам, совместное редактирование исходников в браузере, объектное хранилище, HA, распределённая очередь сборок, управляемая ротация ключей, SCIM endpoint, восстановление на момент времени, тонкие политики строк корпоративных источников и сертификация регуляторного соответствия.

Без нагрузки нет отдельного процесса для каждого приложения: код и данные лежат в PostgreSQL, функции создают контейнер по запросу. Общий API и PostgreSQL продолжают работать; буквально нулевой стоимости простоя нет.
