# Размещение CoShip

## Локальная разработка

`npm ci && npm run dev` запускает API на 127.0.0.1:4300 и интерфейс на 127.0.0.1:5173. Демо-идентификация разрешена только в локальном режиме. Настройки берутся из `.env`, пример — `.env.example`. Для запуска одной собранной службы: `npm run build`, затем `PUBLIC_URL=http://127.0.0.1:4300 npm start`.

## Корпоративная установка

Текущий комплект рассчитан на одну компанию и один экземпляр API. Выберите инфраструктуру и расположение PostgreSQL, резервных копий и журналов. `COSHIP_REGION` — метка, а не механизм переноса данных или доказательство соответствия требованиям локализации. Вход и каталог обращаются к Google/Microsoft; полностью автономная установка без этих провайдеров пока не реализована.

1. Подготовьте Linux-хост с Docker Compose, DNS и TLS reverse proxy. Proxy должен передавать UI и `/api` на `127.0.0.1:4300`. Порт PostgreSQL наружу не публикуется.
2. Зарегистрируйте OIDC web application. Redirect URI: `https://your-domain/api/auth/callback`. Для Google задайте `OIDC_ISSUER=https://accounts.google.com` и `OIDC_ALLOWED_DOMAIN`. Для Microsoft — `OIDC_ISSUER=https://login.microsoftonline.com/<tenant-id>/v2.0` и `OIDC_TENANT_ID`; issuer `common` не используйте.
3. Укажите `COSHIP_ADMIN_SUBJECT`: неизменяемый Google user ID или Microsoft Entra object ID начального администратора. Email не используется как основание для выдачи admin.
4. Заполните `.env`: `COSHIP_MODE=enterprise`, HTTPS `PUBLIC_URL`, OIDC client ID/secret, идентификатор администратора, `COSHIP_MASTER_KEY`, `COSHIP_DIRECTORY_TOKEN`, `POSTGRES_PASSWORD`. Для пароля PostgreSQL в Compose используйте URL-safe значение, например вывод `openssl rand -hex 32`; ключ шифрования — `openssl rand -base64 32`. Для токена каталога сгенерируйте отдельное случайное значение. Сохраните ключи вне Git.
5. Выполните `docker compose --env-file .env -f infra/compose.yaml up --build -d`. При запуске без Compose дополнительно нужен `DATABASE_URL`.
6. Войдите начальным администратором, затем запустите синхронизацию каталога. До первого полного снимка доступ к корпоративным данным закрыт. Назначить второго администратора можно в разделе «Команда».

Миграции выполняет API при старте: роль PostgreSQL должна иметь право создания таблиц/ролей и переключения в `coship_data_runtime`. В комплекте Compose это владелец отдельной БД. Не используйте эту БД как общую для других продуктов. Разделение мигратора и рабочего подключения пока не реализовано.

## Синхронизация каталога

Адаптер — доверенный процесс администратора, отдельно от AI-агента и кода приложений. Он читает пользователей и прямое членство в группах, затем отправляет полный снимок. Вложенные группы не раскрываются. Лимит MVP — 500 пользователей, 30 групп на пользователя; при превышении частичный снимок не отправляется.

Для Google включите Admin SDK Directory API и domain-wide delegation сервисного аккаунта. Выдайте readonly scopes `admin.directory.user.readonly`, `admin.directory.group.readonly`, `admin.directory.group.member.readonly` с префиксом `https://www.googleapis.com/auth/`. Настройте `GOOGLE_SERVICE_ACCOUNT_FILE` и `GOOGLE_DIRECTORY_ADMIN` для делегирования администратору. [Справочник Google scopes](https://developers.google.com/workspace/admin/directory/v1/guides/authorizing).

Для Microsoft создайте отдельный confidential client, выдайте application permission `Directory.Read.All` с согласием администратора и задайте `DIRECTORY_TENANT_ID`, `DIRECTORY_CLIENT_ID`, `DIRECTORY_CLIENT_SECRET`. Используются [список пользователей](https://learn.microsoft.com/en-us/graph/api/user-list?view=graph-rest-1.0) и [прямые членства пользователя](https://learn.microsoft.com/en-us/graph/api/user-list-memberof?view=graph-rest-1.0). Скрытые членства требуют отдельной проверки конфигурации tenant и разрешений.

На хосте с Node.js и установленными зависимостями:

```sh
DIRECTORY_PROVIDER=google COSHIP_SERVER=https://your-domain npm run directory:sync -- --watch
```

Для Microsoft замените провайдера на `microsoft`. Остальные переменные можно передать через защищённое окружение или `.env`. Токен `COSHIP_DIRECTORY_TOKEN` должен совпадать с API. Для собранной установки без devDependencies запускайте `node dist/scripts/sync-directory.js --watch`.

Watcher повторяет полный проход через две минуты после завершения предыдущего. Настройте менеджер процессов и мониторинг ошибок. После пяти минут без успешного снимка обычные операции блокируются; администратор сохраняет возможность восстановления управления. Отключённые или отсутствующие в полном снимке сотрудники теряют сессии; их приложения передаются резервному владельцу либо активному администратору. Каталог не может отключить последнего действующего администратора без замены.

## Изолированные функции

Без runner доступны статика и платформенные данные; публикация пакета с функциями отклоняется. Runner требует Linux, Docker и runtime `runsc`. Установите gVisor по [официальной инструкции](https://gvisor.dev/docs/user_guide/quick_start/docker/) и проверьте его до включения функций.

На отдельном доверенном Linux-хосте:

```sh
docker build -t coship-function:0.1.0 infra/function
npm ci
npm run build
```

Запустите `node dist/apps/runner/src/main.js` с `COSHIP_RUNNER_KEY` (случайный токен минимум 32 символа), `COSHIP_BROKER_ORIGIN` (точный origin API для обратных вызовов), `RUNNER_HOST` и при необходимости `RUNNER_PORT` (по умолчанию 4400). По умолчанию слушается loopback; для отдельного хоста задайте адрес приватного интерфейса.

В API задайте `COSHIP_RUNNER_URL`, тот же `COSHIP_RUNNER_KEY` и `COSHIP_BROKER_URL` — адрес API, доступный runner. Origin этого адреса должен совпадать с `COSHIP_BROKER_ORIGIN`. Если API работает в контейнере, `127.0.0.1` внутри него не указывает на отдельный runner. Ограничьте сетевой доступ между службами и используйте TLS при передаче за пределами доверенного хоста. Публичный доступ к runner не нужен.

Runner имеет доступ к Docker daemon и считается частью доверенной платформы. Гостевые контейнеры не получают Docker socket, сеть, ключи платформы или корпоративные токены. Они создаются на вызов и удаляются после результата/таймаута. Наличие `runsc` проверяется при старте; fallback на обычный runtime отсутствует. Интеграционный запуск на Linux в текущей macOS-среде не выполнялся.

## Сохранность и эксплуатация

PostgreSQL содержит исходники, релизы, записи, права, аудит и зашифрованные секреты. Делайте резервные копии базы средствами PostgreSQL; ключ `COSHIP_MASTER_KEY` храните отдельно и также резервируйте. Без исходного ключа восстановленные секреты недоступны. Проверяйте восстановление в отдельной установке, не поверх рабочей БД. Смена ключа без перешифрования записей не поддерживается.

В локальном режиме для согласованной копии остановите CoShip и сохраните всю `.coship/data`, включая `master.key`. Не публикуйте эту папку как приложение.

Автоархив сохраняет данные и релизы; это не удаление персональных данных по сроку хранения. Аудит очищается после 90 дней; политика удаления прикладных данных настраиваемой пока не является. Health endpoint `/api/health` подтверждает доступность процесса, но не заменяет проверку OIDC, свежести каталога, резервных копий и runner.

TLS proxy, мониторинг, backup automation, HA и приёмка в реальном корпоративном tenant остаются задачами установки. [Текущие границы реализации](implementation.md).
